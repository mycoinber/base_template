# Base Template

Nuxt 3 SSR template with:
- `core` headless/business layer
- theme layer in `themes/parimatch`
- Nitro proxy routes to backend API
- SEO/schema/head assembly centralized in `core/composables`

## Current State

The runtime path is already consolidated around the new layer:
- page data: `core/composables/usePageData.ts`
- page document/head setup: `core/composables/usePageDocument.ts`
- SEO/schema: `core/composables/useSeo.ts`
- navigation: `core/composables/useNavigation.ts`
- site manifest: `core/composables/useSiteManifest.ts`
- themed UI: `themes/parimatch/*`

The repository is still transitional:
- only one real theme is validated in runtime: `themes/parimatch`
- some docs still describe migration history or future multi-theme intent

## Run

Install dependencies:

```bash
npm install
```

Start dev server:

```bash
npm run dev
```

Production build:

```bash
npm run build
```

Preview production build:

```bash
npm run preview
```

## Required Environment

Expected `.env` variables:

```bash
SITE_ID=...
BACKEND_URL=...
SITEMAP_API_BASE=...
MEDIA_STORAGE_URL=...
SLUG=...
```

Theme overrides are read from `NUXT_PUBLIC_COLOR_*`.

## Runtime Flow

1. Nuxt page loads `pages/index.vue` or `pages/[...slug].vue`
2. page data is fetched through `/api/pages` via `usePageData`
3. head/meta/schema/body code blocks are assembled in `usePageDocument`
4. layout/theme components render through `Theme*` components from `themes/parimatch`
5. navigation is fetched through `/api/nav`

## Notes

- `public/site-manifest.json` is generated by `scripts/fetch-manifest.mjs`
- active theme is configured in `theme.config.ts`
- `pages/[...slug].vue` is the canonical catch-all route
